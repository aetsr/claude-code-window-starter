Claude Code 5-Hour Window Starter for macOS

Claude Window Starter is an open-source macOS app that pre-starts and schedules Claude Code's 5-hour usage window around your working hours. It tracks real 5-hour and weekly usage limits, observes server-reported reset times, and schedules lightweight requests so future resets land at more useful times.

Does not increase quota, bypass limits, or reset server timers. Not affiliated with Anthropic.

Features

Adaptive scheduling

Plans anchor requests around your work hours with configurable lead time and 303-minute cadence. Replans from server-observed resets.

Live usage tracking

Shows 5-hour and weekly usage percentages, reported reset times, and local countdowns in the macOS menu bar.

Smart skip logic

Skips redundant anchors when an active window is observed. Suppresses requests during weekly exhaustion.

Sleep/offline aware

Stale actions expire after sleep or offline periods instead of firing as a backlog. No wake alarm needed.

Telegram control

Optional remote status, usage sync, manual runs, work-hours changes, and confirmed actions via Telegram bot.

Transactional installs

Installer stages complete releases atomically with journaled rollback on failure. Preserves existing preferences.

How it works

  1. Set your work hours Configure your timezone, work start/end (e.g. 08:00-17:00), and weekdays in the menu bar app.
  2. Planner schedules anchors The adaptive planner creates anchor times starting 3 hours before work. For 08:00-17:00, this means 05:00, 10:03, 15:06.
  3. Anchor runs at due time The launchd helper sends a small tool-free Haiku request through your Claude Code CLI. This is normal subscription usage.
  4. Replan from observed reset If the server reports an active window, the redundant anchor is skipped and the next one replans from the reported reset time.

Frequently asked questions

Can Claude Window Starter pre-start a Claude Code 5-hour window?

Yes. It schedules a pre-work anchor request that may start a new 5-hour window if you are currently between windows. It sends an ordinary tool-free Haiku request through your signed-in Claude Code CLI, which consumes normal subscription usage.

Is Claude Window Starter a Claude Code warmup tool?

Yes, in the sense of scheduling an early request to start usage. Warmup here does not mean keeping a model loaded or making responses faster — it means opening a usage window earlier.

Does Claude Window Starter bypass Claude Code's usage limits?

No. It does not bypass, increase, reset, or manipulate Claude Code usage limits, quotas, timers, or authentication. It schedules ordinary subscription requests and reads reported usage. Every anchor consumes normal quota.

How does it know the real reset time?

It queries usage through a three-step chain: local cache, Anthropic's OAuth usage endpoint using your existing Claude Code credential, and interactive CLI /usage as fallback. Server-reported reset times are treated as observations; local calculations are estimates only.
